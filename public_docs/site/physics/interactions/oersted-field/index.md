(oersted-problem-statement)=
# Oersted field

::: {admonition} Scope and qualification boundary
:class: note

The Oersted interaction is a prescribed magnetic effective field generated by a current source.
The four solver/device lanes below are documented separately.
:::

This page is the canonical physics owner for Oersted field generation. The Python constructor
reference is expanded in {doc}`../../../python-api/interactions/oersted-field`. Geometry,
current transport as a general API, studies, and output scheduling retain their own canonical
pages.

## Physical and numerical hierarchy

The implementation follows this hierarchy:

1. physical domain: prescribed charge current $\mathbf J$ generates an H-field;
2. solver family: FDM grid or FEM shared mesh;
3. execution backend: CPU reference/native path or GPU CUDA path;
4. interaction realization: exact infinite-cylinder field or regularized midpoint Biot-Savart field.

The analytic cylinder is the exact solution for the stated infinite, straight, uniformly filled
conductor. The midpoint path is an explicit numerical approximation to the volume Biot-Savart
integral. A planner resolution to either realization is not a claim that a finite conductor,
contact, return path, or current crowding problem has been solved.

(oersted-governing-equations)=
## Governing equations

### Analytic infinite cylinder

Let $\hat{\mathbf a}$ be the current-flow axis after native normalization and let $\mathbf c$ be
a point on that axis. For a destination $\mathbf x$, define

```{math}
:label: eq-oersted-perpendicular-vector
\mathbf r_\perp(\mathbf x)
=\mathbf x-\mathbf c-
\bigl[(\mathbf x-\mathbf c)\cdot\hat{\mathbf a}\bigr]\hat{\mathbf a},
\qquad
r=\|\mathbf r_\perp\|.
```

For a cylinder of radius $R$ carrying total current $I(t)$, Ampere's law gives

```{math}
:label: eq-oersted-cylinder-magnitude
H_\varphi(r,t)=
\begin{cases}
\dfrac{I(t)\,r}{2\pi R^2},&0<r<R,\\[6pt]
\dfrac{I(t)}{2\pi r},&r\ge R,\\[6pt]
0,&r=0.
\end{cases}
```

The vector field follows the right-hand rule:

```{math}
:label: eq-oersted-cylinder-vector
\mathbf H_{\mathrm{oe}}(\mathbf x,t)
=H_\varphi(r,t)\,
\frac{\hat{\mathbf a}\times\mathbf r_\perp}{r}
\qquad (r>0),
\qquad
\mathbf H_{\mathrm{oe}}(r=0,t)=\mathbf 0.
```

The value on the axis is set to zero to avoid division by zero. The inside expression is the
uniform-current result; the outside expression is the line-current result. The implementation
does not use the outside law inside the conductor.

### Time dependence

The spatial basis is separated from the current envelope:

```{math}
:label: eq-oersted-current-envelope
I(t)=I_0g(t).
```

The implemented envelope forms are

```{math}
:label: eq-oersted-time-envelopes
g(t)=
\begin{cases}
1,&\text{Constant},\\
\sin(2\pi f t+\phi)+o,&\text{Sinusoidal},\\
\mathbf 1_{[t_{\mathrm{on}},t_{\mathrm{off}})}(t),&\text{Pulse}.
\end{cases}
```

The pulse interval is half-open: $g(t_{\mathrm{on}})=1$ and
$g(t_{\mathrm{off}})=0$. Piecewise-linear and sinc-pulse objects are valid public
time-dependence objects, but the Oersted planner rejects them for this interaction rather than
approximating them as one of the three supported forms.

### Prescribed-current volume field

For a prescribed current density in source volume $\Omega_J$, the continuum field is

```{math}
:label: eq-oersted-biot-savart
\mathbf H_{\mathrm{oe}}(\mathbf x)
=\frac{1}{4\pi}\int_{\Omega_J}
\frac{\mathbf J(\mathbf x')\times(\mathbf x-\mathbf x')}
{\|\mathbf x-\mathbf x'\|^3}\,\mathrm dV'.
```

The current source is prescribed; Fullmag does not currently solve the electromagnetic transport
equation that would determine $\mathbf J$ for OerstedField.

### Regularized midpoint realization

The current FEM and FDM generalized paths use source-cell or source-tetrahedron midpoints. For
source element $s$,

```{math}
:label: eq-oersted-midpoint
\mathbf H_{\mathrm{oe}}(\mathbf x_i)\approx
\frac{1}{4\pi}\sum_{s\in\mathcal S}
\frac{\mathbf J_s\times(\mathbf x_i-\mathbf x_s)}
{\bigl(\|\mathbf x_i-\mathbf x_s\|^2+a_s^2\bigr)^{3/2}}V_s,
\qquad
a_s=\left(\frac{3V_s}{4\pi}\right)^{1/3}.
```

This is a regularized midpoint quadrature rule. It is not the exact field of each tetrahedron or
cell, and it must not be presented as equivalent to the analytic cylinder. The native planner
uses tet4 elements for generalized FEM. The FDM path uses cell centres and the same
equivalent-volume regularization.

### Exact cylindrical reduction of a current source

When a source-bound current is uniform, cylindrical, and parallel to the cylinder axis, the
planner reduces the source to the analytic-cylinder current

```{math}
:label: eq-oersted-current-reduction
I=(\mathbf J_0\cdot\hat{\mathbf a})\,\pi R^2,
\qquad
\mathbf J_0\parallel\hat{\mathbf a}.
```

The planner rejects a transverse component rather than silently discarding it. For a
non-cylindrical source, the planner selects the midpoint field realization when the selected lane
has the required source mesh/grid data.

(oersted-assumptions-and-validity)=
## Assumptions and validity limits

- The analytic model is an infinite, straight, uniformly filled conductor. It omits finite-length
  end effects, contacts, return paths, current crowding, skin effect, and displacement current.
- Current may be positive or negative; its sign reverses field chirality. Radius must be strictly
  positive. The Python constructor converts current to float but does not itself reject a
  non-finite value; ProblemIR validation rejects non-finite current values.
- Python center and axis arguments must contain exactly three values. The Python vector helper
  performs shape conversion; finite/non-zero axis legality is enforced by ProblemIR and
  planner/native validation. FEM normalizes the cylinder axis. FDM CUDA accepts only exact
  $(0,0,1)$ for the analytic cylinder.
- OerstedField(model="from_current_solution") requires a named CurrentTransport with
  model="prescribed_density", a solve_region, and a source density parallel to a cylindrical
  axis for exact reduction.
- CurrentTransport(model="ohmic_poisson") is representable in Python but is not an executable
  Oersted source in the current planner; it is not silently treated as prescribed density.
- A non-cylindrical source uses regularized midpoint Biot-Savart and is subject to tet4/source
  selector restrictions in FEM and a public active-source-cell limit of 4096 in FDM.
- The interaction adds $\mathbf H_{\mathrm{oe}}$ in A/m. It does not multiply by $\gamma$,
  $\alpha$, or $\mu_0$, and it does not materialize an exchange-like or Zeeman-like scalar
  energy.
- Conservative relaxation rejects Oersted terms until identical field-energy parity is validated
  for the selected lane. Dynamic time evolution and conservative minimization are different
  requests.

(oersted-problem-ir)=
## Canonical ProblemIR and normalization

The following executable, runtime-independent example uses a cylindrical source-bound current.
It records the authored source, while the planner later resolves it to an analytic cylinder.

```python
# %% Imports and SI constants
import json
import fullmag as fm

nm = 1.0e-9
ps = 1.0e-12

# %% Magnetic cylinder and source current
pillar_geometry = fm.Cylinder(
    radius=50 * nm,
    height=100 * nm,
    name="pillar",
)
material = fm.Material(
    name="Permalloy",
    Ms=800.0e3,
    A=13.0e-12,
    alpha=0.01,
)
magnet = fm.Ferromagnet(
    name="pillar",
    geometry=pillar_geometry,
    material=material,
    m0=fm.texture.uniform((0.0, 0.0, 1.0)),
)
transport = fm.CurrentTransport(
    name="drive",
    model="prescribed_density",
    current_density=(0.0, 0.0, 5.0e10),
    solve_region="pillar",
)

# %% Oersted source-bound term and output
term = fm.OerstedField(source="drive")
study = fm.TimeEvolution(
    dynamics=fm.LLG(),
    outputs=[fm.SaveField("H_oe", every=ps)],
)
problem = fm.Problem(
    name="oersted_source_bound",
    magnets=[magnet],
    energy=[fm.Exchange(), term],
    current_modules=[transport],
    study=study,
    discretization=fm.DiscretizationHints(
        fdm=fm.FDM(cell=(2 * nm, 2 * nm, 2 * nm)),
    ),
)

# %% Canonical lowering; no native solver is launched
problem_ir = problem.to_ir(include_geometry_assets=False)
assert problem_ir["energy_terms"][1] == {
    "kind": "oersted_field",
    "model": "from_current_solution",
    "source": "drive",
}
assert problem_ir["current_modules"][0]["current_density"] == [0.0, 0.0, 5.0e10]
print(json.dumps(problem_ir, indent=2))

# %% Direct analytic-cylinder authoring is a separate requested intent
cylinder_term = fm.OerstedCylinder(
    current=5.0e-3,
    radius=50 * nm,
    center=(0.0, 0.0, 0.0),
    axis=(0.0, 0.0, 1.0),
    time_dependence=fm.Sinusoidal(frequency_hz=1.0e9, offset=0.25),
)
print(cylinder_term.to_ir())
```

      "kind": "current_transport",
      "name": "drive",
      "model": "prescribed_density",
      "current_density": [0.0, 0.0, 50000000000.0],
      "solve_region": "pillar"

(oersted-round-trip-and-failure-semantics)=
## Requested intent, resolved execution, and failure semantics

The canonical script and ProblemIR preserve requested intent:

- the user-requested object is either OerstedCylinder or OerstedField;
- source name, current density, geometry binding, vector values, envelope, output request, and SI
  values remain inspectable;
- Python lowering does not select CPU/GPU, precision, midpoint versus analytic realization, or
  runtime device.

The planner adds resolved execution separately. A resolved record must identify solver family,
CPU/GPU device, precision, analytic versus midpoint realization, source element/cell selection,
time-envelope policy, and qualification evidence. The backend plan stores the realized field basis
or final field values, but that plan data is not a replacement for authored intent.

Validation errors include:

- non-positive radius, non-finite current, non-finite centre/axis, or a zero axis at IR validation;
- an empty or unknown OerstedField.source;
- a source that is not a CurrentTransport;
- missing solve_region or a region/geometry name that cannot be resolved;
- non-parallel prescribed density for the exact cylindrical reduction;
- non-tet4 FEM source elements, unsupported mesh selectors, or missing source elements;
- more than 4096 active source cells in the generalized FDM midpoint path;
- PiecewiseLinear or SincPulse selected as an Oersted envelope;
- CUDA analytic-cylinder axis other than exact +z, or CUDA time dependence other than Constant;
- an H_oe output without an Oersted term;
- conservative relaxation with Oersted because field-energy parity is not established.

Unsupported combinations are not silently changed to a different source model, precision, device,
or CPU fallback. A successful Python to_ir call proves representability only; a successful planner
call proves only capability checks, and GPU qualification additionally needs executed-device
evidence.

(oersted-discrete-realization)=
## Solver and execution realizations

### FDM solver family

#### FDM CPU execution backend

The CPU FDM path uses cell-centre positions. An OerstedCylinder is evaluated with the analytic
inside/outside profile and added by the native Oersted field routine. A source-bound cylindrical
CurrentTransport is reduced to the same analytic profile after current projection. A
non-cylindrical source is lowered by the planner to a per-cell midpoint field; the active source
cell count is limited to 4096. CPU accepts Constant, Sinusoidal, and Pulse cylinder envelopes.

The CPU lane is the reference implementation for double-precision comparison, but source
presence does not by itself qualify generalized midpoint convergence or full cross-backend parity.

#### FDM GPU execution backend

The native CUDA path precomputes a unit-current analytic-cylinder field, uploads the basis in the
selected precision, and scales/injects it in the effective-field path. It currently requires the
exact axis $(0,0,1)$ for an analytic cylinder and rejects Sinusoidal, Pulse, PiecewiseLinear, and
SincPulse cylinder envelopes because every RK stage does not yet receive the required source time.
The planner-generated generalized field is uploaded as resolved per-cell values; it is not
silently reconstructed as an analytic cylinder.

The FDM GPU lane must be reported with execution precision and device identity. Source-level CUDA
coverage, compilation, or a skipped test is not GPU parity evidence.

### FEM solver family

#### FEM CPU execution backend

The native MFEM CPU path has two distinct field ownership cases:

1. an analytic cylinder basis is normalized and initialized once, then materialized at the
   accepted/RK evaluation time from the current envelope;
2. a generalized source-bound or planner-produced field is imported as final nodal values and is
   added without cylinder scaling.

The dispatcher adds the realized field exactly once to $\mathbf H_{\mathrm{eff}}$. Generalized
Biot-Savart lowering currently requires tet4 source elements and an element selector. Constant,
Sinusoidal, and Pulse cylinder envelopes are handled on the CPU path.

#### FEM GPU execution backend

The native CUDA FEM path keeps the analytic unit-current basis and realized H_oe buffers on the
device. The RK field contribution evaluates supported envelope values at the stage time, scales
the basis, and accumulates the realized field. An explicit generalized field is final H_oe data
and is not rescaled as though it were a unit-current cylinder basis.

The GPU and CPU paths therefore share the physical field contract but not memory ownership,
stage-time handling, or field materialization. A current revision requires separate executed-device
qualification for field values, accepted-time snapshots, rollback, and CPU/GPU parity.

### Support and qualification matrix

| Solver | Device | Current implementation | Honest qualification state |
|---|---|---|---|
| FDM | CPU | Analytic cylinder and planner-generated midpoint field; Constant, Sinusoidal, and Pulse cylinder envelopes | Implemented reference path; generalized convergence and parity require current evidence |
| FDM | GPU | CUDA unit-current cylinder basis and resolved generalized field upload; analytic cylinder is exact +z and Constant-only | Implemented source path; executed-device parity and precision qualification are separate |
| FEM | CPU | MFEM nodal cylinder basis, accepted/RK envelope materialization, and final explicit generalized nodal field | Native contract and local tests exist; generalized approximation convergence remains separate |
| FEM | GPU | Device-resident cylinder basis and realized H_oe accumulation at RK stage times | Native contract exists; executed-device field/snapshot/parity evidence is required |

tests cover source-region resolution, axis alignment, exact-cylinder preference, midpoint tet4/FDM
paths, and active-cell limits. The contract's analytic checks include inside, outside, axis,
direction, half-open pulse edges, envelope scaling, explicit no-rescaling, and realized H_oe
observable ownership. GPU claims require executed-device evidence; skipped or source-only tests
are not parity evidence.

(oersted-limitations)=
## Limitations and deferred work

- No ohmic-Poisson current solve, finite-contact solve, return-path solve, or conductor end effect.
- No hybrid current-to-Oersted coupling.
- General midpoint Biot-Savart is regularized and approximate; it is not interchangeable with the
  exact infinite-cylinder field.
- FDM generalized lowering is bounded by active source-cell count and is not the multilayer FDM
  path.
- FDM CUDA has stricter axis and envelope gates than CPU and FEM.
- No standalone Oersted energy scalar or conservative Oersted minimization qualification.
- PiecewiseLinear and SincPulse are not executable Oersted-cylinder envelopes on current lanes.
