# Selecting workflow skills

Read a skill when the user names it or its description matches the actual task. A keyword overlap alone is insufficient. Read each selected skill once; open supporting references only when the current step needs them. Do not load both a repository skill and its plugin duplicate.

System and developer instructions govern the session. Within their bounds, explicit user instructions and existing authorization take precedence over skill guidelines. Follow applicable project safety and scientific contracts. A skill does not authorize commits, external messages, deployments, permission changes, or deletion.

Choose the smallest useful workflow: investigate a defect, plan a multi-step change, or execute an already clear request. Do not require brainstorming, a written plan, or another approval for every task. If a skill actually blocks authorized work, identify its exact file and rule, explain the conflict, and continue independent work.

Use only tools available in the current host. Consult [Codex tool adaptation](references/codex-tools.md) if a workflow needs a host-specific mapping. Do not change host configuration merely to make a skill applicable.
