# Review brief

Use the available review/delegation mechanism and preserve configured model/effort unless an override is authorized. Provide the actual requirements, affected files or exact diff, source identity, applicable constraints, and existing verification evidence. Identify whether the scope is a task, branch, staged diff, or uncommitted change.

Review is read-only on the shared checkout and index. Read the diff and the relevant surrounding code or callers needed to judge its behavior. A diff excerpt or implementer report may omit important context; investigate a concrete concern rather than treating either as proof.

Evaluate requirement coverage, correctness, security, data integrity, scope, maintainability, and applicable project/scientific contracts. Distinguish a defect from a preference. Reuse valid test evidence, and run a focused check when a concrete concern is unanswered. Follow mandatory project gates; report unverified runtime/physics lanes explicitly.

Return actionable findings with severity, file location, affected behavior, and evidence. Include a concise assessment and any verification gaps. No mandatory praise section or speculative cleanup list. Do not pre-judge findings because a plan example contains the same flaw, and do not post comments or mutate Git without authorization.
