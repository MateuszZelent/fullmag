`examples`, `fullmag-cli`, `fullmag-engine`, `fullmag-authoring` i

121 wymagających runtime, 1211 opisujących intencję i 2817 historycznych.

```text
Python DSL / UI authoring
  -> ProblemIR
  -> validation i planner FEM
  -> runner + requested/resolved execution
  -> fullmag-fem-sys + native/include/fullmag_fem.h
  -> backends/fem/src/api.cpp
  -> CPU/MFEM lub strict GPU/CUDA
  -> fields, energies, metrics, artifacts i session resources
```

## 6. Bramki runtime

| Bramka | Stan przy publikacji tego manifestu | Granica dowodu |
|---|---|---|
| `just ensure-managed-fem-runtime` | PASS po kontenerowej przebudowie stabilnego źródła | świeżość zarządzanego bundla w tej iteracji |
| `just verify-fem-relaxation-source-contract` | PASS | ownership i call topology, nie równanie fizyczne |
| `just verify-fem-relaxation-runtime` | PASS | 4-krokowy smoke CPU/GPU overdamped, PG-BB, NCG i CPU TPI |
| `just verify-fem-relaxation-convergence` | PASS po ponowieniu na stabilnym bundlu | kompletna macierz 16-krokowa spełniła wymagany spadek energii i limit wzrostu momentu |
| `just verify-fem-relaxation-cpu-gpu-consistency-smoke` | PASS: 6/6 wierszy, 3/3 par | trywialny uniform-equilibrium exchange-only plumbing smoke; wykonano 0 lub 1 krok |

Żadna z tych bramek nie zawiera pełnej macierzy PMA, DMI, thermal, STT, Oersted,
periodic DMI, ostrych map materiałowych, wymuszonego demag-nonconvergence i hybrid
Robin failure. Dlatego smoke PASS nie awansuje tych modułów do `physics_validated`.
