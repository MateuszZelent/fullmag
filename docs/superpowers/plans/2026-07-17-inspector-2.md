# Inspector 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver one elegant, accessible, state-honest Inspector shell for every registered Control Room selection family.

**Architecture:** Add a descriptor-driven shell above the existing inspector registry and retain each panel's domain/resource logic. Centralize generic layout and interaction CSS, migrate panels to shared sections/form primitives, and expose a typed edit-session bridge for staged, live-viewport, and immediate behavior.

**Tech Stack:** React 19, TypeScript, Radix-based shared UI primitives, CSS custom properties, Vitest/Testing Library, Playwright browser smokes.

## Global Constraints

- Preserve all unrelated and pre-existing dirty-worktree changes.
- Use only `fm-` CSS classes and `--fm-*` design tokens.
- Do not add a heavy UI dependency or direct component `fetch()` calls.
- Do not render or request an image, canvas, viewport snapshot, thumbnail, screenshot, or preview placeholder in Inspector.
- Default width 416 px; minimum 360 px; maximum `min(560px, 38vw)`; resize target 6 px; double-click resets; persist width.
- Shell rows are header, 40 px tabs, scrolling content, and 56 px action bar; only content scrolls.
- Maximum four visible tabs; Visualization tabs are exactly Overview, Properties, Display, Diagnostics.
- Apply and Reset must reflect the active panel's real edit semantics; never present a decorative or non-persisting edit control.
- Keep diagnostics demand-driven and inactive-tab work at zero.
