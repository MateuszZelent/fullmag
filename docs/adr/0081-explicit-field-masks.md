# ADR 0081: explicit masks for field excitation

- Status: accepted for implementation
- Date: 2026-11-13
- Complements: [ADR 0019](0019-regional-field-drive-and-stage-time-semantics.md)
- Physics contract: [`docs/physics/0922-masks-for-field-excitation.md`](../physics/0922-masks-for-field-excitation.md)
- Data contract: [`docs/specs/mask-function-v1.md`](../specs/mask-function-v1.md)
- Design and plan: [`docs/superpowers/specs/2026-11-13-field-masks-design.md`](../superpowers/specs/2026-11-13-field-masks-design.md),
  [`docs/superpowers/plans/2026-11-13-field-masks.md`](../superpowers/plans/2026-11-13-field-masks.md)

## Context

mumax3 users excite spin waves with `B_ext.Add(mask, f(t))`: a vector mask filled
by the script, multiplied by a scalar function of time. The mask is stored on the
device once; every field evaluation adds `f(t) · mask` with one scalar computed on
the host.

Fullmag has the same runtime structure on all four lanes: FDM keeps a dense
per-cell field basis and FEM a nodal basis, and both add `multiplier(t) · basis`
at every Runge–Kutta substage. What it lacks is a way to author such a mask.
`RegionalFieldDrive` offers a fixed set of analytic profiles and built-in
waveforms on a global, object or region target. A region is an exclusive
partition of a magnet, so a region target cannot express a support that overlaps
other regions.

## Decision

1. **A mask is a prescribed field, independent of regions.** It has a support
   (a shape placed in a target magnet) and no material. Regions keep their
   meaning: partition, material, initial magnetization, inter-region exchange.
   The conductor-based antenna module is unchanged.
2. **The primitive is the mumax3 level (L0).** A mask field drive is a list of
   terms `(mask, time)`. A mask is written by hand, either as a restricted Python
   function `(x, y, z, parameters…) → (Bx, By, Bz)` or as an array filled in
   ordinary Python (`set_vector`, usually in a loop inside a user function). A
   time function is a restricted Python function `(t, parameters…) → number`.
   Values are given where the function is used (`fm.mask(f, name=value, …)`),
   not in its `def`.
3. **Everything above L0 only produces L0 terms.** User modules (plain Python
   returning terms), ready antennas in `fullmag.antennas`, and the single-function
   form `f(x, y, z, t)` (split into space × time terms) add no solver concept.
4. **The antenna lives in the script.** A script written by hand and a script
   generated by the Control Room use the same calls. The Control Room edits
   function masks (parameters and equations) and the arguments of ready antennas;
   it shows and keeps array masks written by user loops without editing them.
5. **Functions are transpiled, never called by a solver.** `ProblemIR` stores
   equations (`field_expr.v1`); one Rust crate, `fullmag-expr`, parses and
   evaluates them for the CLI, the API and the planner.
6. **The runtime is the existing basis × multiplier path.** The planner evaluates
   a function mask once per cell (cell centre) or copies/resamples an array mask.
   The time function is compiled to bytecode; the host evaluates one number per
   term per field build. No equation is evaluated per cell during a run.
7. **Lanes.** FDM CPU and FDM CUDA realize mask field drives on the single
   grid. FEM CPU and FEM GPU evaluate the same masks at the nodes of the
   target's magnetic elements and feed the existing pre-projected nodal basis
   (regional-drive ABI v4, waveform kind `HOST_EXPRESSION`); the IR, the crate,
   the Python API and the UI are the same for all four. Multilayer FDM and the
   Rust FEM reference reduction refuse them with
   `mask_field_drive_unsupported_lane`.
8. **Stages and clock.** An antenna is authored by creation and enters the
   physics at a pipeline point with `study.stages.add_field_drive(antenna, …)`
   (stage action `add_mask_field_drive`, beside the existing `add_field_drive`) or
   for the whole study with `study.field_drives.add(antenna)`;
   `remove_field_drive` removes either kind. `t` of a time function follows the
   stage clock of regional drives (ADR 0019): `stage_local` by default, `absolute`
   on request (the `t` of mumax3).

## Consequences

- `RegionalFieldDrive`, `FieldTargetIR` and `TimeDependenceIR` are not changed. A
  problem without masks serializes and plans exactly as before.
- A time-dependent mask term, like any time-dependent drive today, makes FDM CUDA
  use the host-driven step loop instead of the captured adaptive graph.
- An array mask is data on a regular lattice. It is exact when the lattice is the
  FDM grid and is resampled otherwise.
- The single-function form rejects functions that are not a finite sum of
  space × time factors.

## Alternatives considered

- **A new `FieldTargetIR` variant for a selection support.** Rejected: the type is
  shared with the solved-antenna code in 14 exhaustive matches.
- **Equations as text in the script.** Rejected by the users: a mask should read
  as a function or as the mumax3 loop.
- **One function `f(x, y, z, t)` as the primitive, evaluated per cell during the
  run.** Rejected as the primitive: it costs an equation evaluation per cell per
  substage on every lane and hides the mumax3-level control. It remains available
  as a layer that is split into L0 terms.
