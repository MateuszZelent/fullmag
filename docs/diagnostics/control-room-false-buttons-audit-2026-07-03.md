# Control Room false-button audit - 2026-07-03

Scope: `apps/control-room` frontend command and button surfaces that appear to perform runtime/backend work. The audit focused on central command registry contributions, ribbon actions, context-menu commands, and inspector actions that dispatch through the registry.

Definition used here:

- **false success**: a user-facing command returns `status: "completed"` without API submission, backend transaction, resource mutation, file download, or meaningful local state change.
- **unregistered visible action**: a visible ribbon/menu action calls `kernel.commands.execute(...)` with an id that is not registered. This fails as an unknown command rather than faking success, but it is still a visible unimplemented button.
- **not counted**: disabled placeholders that cannot fire, static status rows, local-only display toggles that mutate visualization/local state, and commands that call `ControlRoomApi`, model transactions, resource hooks, or browser downloads. Disabled menu buttons are counted when the shared ribbon button leaves them clickable.
